# MegaContext KV Caching - Product Requirements Document (PRD)

## 1. Overview

This document specifies the KV caching subsystem for the MegaContext / WorkingContext (MC/WC) architecture with multi-LOD gists and dynamic focusing.

The goal is to support:

- A large MegaContext (MC) stored on disk (full LOD0 tokens + all gists).
- A smaller WorkingContext (WC) kept in memory and fed to the transformer.
- Dynamic expansion of gists (loading their children from MC into WC).
- Dynamic collapse of nodes to keep WC within a length budget.
- Efficient incremental updates to the KV cache whenever WC changes.

The KV caching layer must support **two interchangeable strategies**:

1. **Option 1: Dirty-Suffix Prefill (Time-Sorted WC)**  
   WC is serialized in temporal order. Expansions insert children at their correct time positions. KV cache is repaired by recomputing a dirty suffix.

2. **Option 3: Append-Only + Window Recompute (KV Index Decoupled From Time)**  
   WC is append-only for KV indexing. Expansions append children at the end. Local KV windows are selectively recomputed so that important queries (e.g. the tail) can see newly added children.

Both options share common abstractions and APIs so that the implementation can switch between them via configuration.

---

## 2. Scope and Assumptions

- This PRD covers **inference-time** KV caching only.
- Training can assume full recomputation and does not need to use these strategies.
- The transformer already supports:
  - Multi-LOD nodes (LOD0 tokens, LOD1/LOD2+ gists).
  - 2D / Gaussian positional encoding with time center mu and span sigma.
  - An attention mask builder that can use mu, sigma, and LOD info.
- LensNet and the Context Manager already decide **which** gists to expand or collapse. The KV layer only needs to handle **how** to update KV given those decisions.

---

## 3. Functional Requirements

1. **Dynamic WC Updates**
   - Apply a batch of expansions (load children of selected gists into WC).
   - Apply a batch of collapses (remove leaf nodes from WC).
   - Keep WC size under a configured limit (WC_len_max).

2. **KV Cache Consistency**
   - After WC changes, the KV cache must be consistent with:
     - The new WC serialization (Option 1) or KV slot mapping (Option 3).
     - The attention masks (no causal violations).
   - Any node that can legally attend to a new child must see that child in its K/V set after repair.

3. **Strategy Switching**
   - Support a configuration flag to select:
     - `kv_mode = "dirty_suffix"` (Option 1)
     - `kv_mode = "append_window"` (Option 3)
   - Both modes must share the same external API to the rest of the system.

4. **LensNet Integration**
   - Focusing (expand/collapse) occurs only on scheduled steps (e.g. every N AR steps).
   - KV repair is triggered immediately after WC is updated by the Context Manager.

---

## 4. Performance Requirements

- WC size: up to at least 64k nodes, target 128k.
- Full prefill over WC may be too expensive to repeat frequently.
- The KV subsystem must:
  - Avoid full re-prefill except in fallback / recovery cases.
  - Exploit reuse of existing KV entries where possible.

Target complexity per focusing cycle:

- **Option 1:** `O(num_layers * dirty_suffix_len)`
- **Option 3:** `O(num_layers * (num_new_children + window_size))`

Where `dirty_suffix_len`, `num_new_children`, and `window_size` are expected to be much smaller than WC length on average.

---

## 5. Option 1 - Dirty-Suffix Prefill (Time-Sorted WC)

### 5.1 Behavior

- WC is a list of nodes sorted by their time coordinate mu.
- When expanding a gist g:
  - Its children are inserted into WC at positions consistent with their mu.
- After all expansions and collapses:
  - Let `i_min` be the smallest index where a new node was inserted or an old node was removed.
  - All WC positions `< i_min` remain unchanged and their KV entries remain valid.
  - All WC positions `>= i_min` form a **dirty suffix** that must be recomputed.

### 5.2 Requirements

- Provide a function that:
  - Accepts the updated, time-sorted WC.
  - Identifies `i_min`.
  - Recomputes only positions `i_min .. end` layer by layer, reusing KV entries for `0 .. i_min-1`.

- Collapses:
  - When nodes are removed, subsequent indices shift left.
  - The same dirty-suffix logic applies, using the earliest affected index as `i_min`.

---

## 6. Option 3 - Append-Only + Window Recompute

### 6.1 Behavior

- WC serialization for KV is append-only:
  - Each node occupies a KV slot.
  - Expansions append children to the end of the WC list.
  - Collapses mark KV slots as inactive but do not force reindexing.
- Time (mu) is represented in the positional encoding and masks, not by the KV index.

### 6.2 New Children

- When children are appended:
  - The system computes their K/V using the current cache (treat them like additional decoded positions).
  - Existing nodes do not automatically see these children, because their Q, K, V are frozen.

### 6.3 Window Recompute

- To allow important queries (for example, the current tail) to attend to the newly added children:
  - The system defines one or more **recompute windows** (lists of WC positions).
  - For each window:
    - Clear K/V for those positions.
    - Re-run forward passes for those positions only, with:
      - Earlier nodes (and newly appended children) as K/V context.
- A common pattern:
  - Tail window: the last W WC nodes.
  - Optionally, additional windows around nodes that requested expansions (LensNet interest events).

---

## 7. Interaction With LensNet and Context Manager

- LensNet outputs a signed routing score per gist.
- Context Manager decides:
  - Which gists to expand (and thus whose children to load).
  - Which leaves to collapse to stay within WC_len_max.

KV subsystem responsibilities:

- Take a list of expansions and collapses from the Context Manager.
- Update WC serialization and KV cache according to the configured strategy.
- Ensure the next AR step sees a KV state that matches the updated WC and masks.

---

## 8. External API Requirements

The KV subsystem should expose functions such as:

- `apply_wc_updates(expansions, collapses)`  
  Applies the WC structural changes and triggers the KV repair for the active strategy.

- `kv_repair_dirty_suffix(i_min)` (Option 1)  
  Recompute K/V for WC positions `>= i_min`.

- `kv_append_children(children)` (Option 3)  
  Allocate KV slots and compute K/V for newly appended children.

- `kv_recompute_windows(windows)` (Option 3)  
  For a set of WC index ranges or slot lists, clear and recompute K/V.

- `reset_full_prefill(wc)`  
  Fallback method: recompute KV from scratch over the whole WC.

---

## 9. Success Criteria

- For fixed WC and mask configuration, full prefill and incremental KV repair must produce identical logits for the tail position (within numerical tolerance).
- Focusing every N steps with either KV strategy should not significantly degrade throughput compared to a model with no focusing and no MC/WC split, given similar effective context length.
- Both strategies must be testable independently behind a configuration flag.
