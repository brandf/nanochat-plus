# Product Requirements Document (PRD)
## Project: NanoChat-LM + Multi-LOD GistNet + Tree Context POC

---

## 1. Overview

This proof-of-concept (POC) extends the existing **nanochat** minimal LLM codebase with:

- A **multi-level-of-detail (LOD) hierarchical context representation** built as a tree over the token sequence.
- A lightweight, **local G→1 summarization network (GistNet)** that turns small groups of child latents into single “gist” vectors.
- A **tree flattening scheme** that presents the entire tree (tokens + gists at multiple scales) as a single causal sequence to a standard decoder-only transformer.
- A **multi-objective training scheme** combining:
  - Cross-entropy (CE) loss on token-level (LOD0) nodes.
  - Mean squared error (MSE) loss on higher-LOD nodes, predicting “future gists” to encourage good summarization.

The POC should remain as close as reasonably possible to the nanochat style: small, readable, hackable.

---

## 2. Goals and Non-Goals

### 2.1 Goals

1. **Integrate GistNet**  
   Implement a lightweight, local summarization module that:
   - Takes `G` child embeddings of dimension `d`.
   - Produces a single `d`-dimensional gist vector.
   - Is applied repeatedly to construct higher-LOD nodes.

2. **Hierarchical LOD Tree Construction**
   - Build a multi-LOD tree from a token sequence, with:
     - LOD0: tokens.
     - LOD1: gists summarizing fixed-size groups of tokens (e.g. 4 or 8).
     - LOD2+: gists summarizing groups of LOD1 gists, etc.
   - Each node has:
     - Latent vector.
     - Level (LOD index).
     - Span definition over the underlying tokens.
     - Span statistics: center time `μ` and variance `σ`.

3. **Tree Flattening into a Causal Sequence**
   - Flatten all nodes (tokens + gists) into a single sequence for the transformer.
   - Enforce **children-before-parent** ordering:
     - Every node’s index is strictly greater than the index of all its descendants.
   - Place higher-LOD nodes **inline** after their children (not all at the end), so later tokens/gists can attend to higher-level gists in the past.

4. **Gaussian 2D RoPE Integration**
   - Extend positional encoding to use 2D information per node:
     - `μ`: time coordinate (e.g. span center or span end).
     - `σ`: scale / variance representing the span length / LOD.
   - Apply this 2D positional information via a “Gaussian RoPE”-style rotary embedding in Q/K space.
   - Preserve the “nothing shifts in time” property: if nodes are dropped, surviving nodes still use their original `(μ, σ)`.

5. **LOD Dropout and Repacking**
   - Implement node-level dropout with constraints:
     - Never drop the **last node** of each LOD (per sequence).
     - A parent can only be dropped if **all its children** are dropped.
   - After dropout, repack kept nodes into a contiguous sequence and recompute index ordering while preserving each node’s `(μ, σ)` and level.

6. **Multi-Scale Losses**
   - LOD0 (tokens):
     - Use standard CE loss to predict the next token in the underlying token sequence.
   - LOD>0 (gists):
     - Use MSE loss between:
       - The model’s predicted future gist at that LOD (from the flattened tree).
       - A “teacher gist” computed from a *future span* of child-level latents using GistNet.
     - `teacher_gist` is computed offline (no gradient) and is not fed back as input to avoid information leakage.
   - Combine CE and MSE losses with configurable weights.

7. **POC Training Configuration**
   - Provide a small, runnable training script:
     - Synthetic or simple text dataset is acceptable.
     - Configurable parameters for:
       - Group size `G` per LOD.
       - Number of LOD levels.
       - Sequence length.
       - Loss weights.
   - Demonstrate that training runs end-to-end and gists are being updated.

8. **Prepare for Future Inference Tricks**
   - Architect the modules so that:
     - GistNet can be called incrementally during inference (e.g. after every G new tokens).
     - Tree construction and flattening logic can be reused or adapted for inference-time context selection.
   - Implementation of inference-time “draft” behavior is **not** required in this POC, but should not be blocked by design decisions.

### 2.2 Non-Goals

- Scaling to production-sized models or datasets.
- Implementing advanced sampling or “draft-guided” decoding at inference time.
- Implementing arbitrary tree structures beyond simple regular hierarchies (e.g. dynamic segmentation based on content).
- Highly optimized CUDA kernels or specialized hardware support (standard PyTorch is sufficient).
- Full long-context benchmarks; only sanity-check style experiments are required for the POC.

## 4. Functional Requirements

### 4.1 GistNet

**Inputs:**

- `x_children`: tensor of shape `[G, d_model]` (G child latents).
- `level`: scalar LOD index (int) or tensor `[1]`.
- `mu`: scalar center time (float; could be token index or normalized).
- `sigma`: scalar variance / scale (float; monotonic with span length).

**Behavior:**

- Construct a single query vector:
  - `q_in = q_base + E_level[level] + E_span(span_features)`
  - Where:
    - `q_base ∈ R^d_model` is a learned vector.
    - `E_level` is an embedding table mapping LOD indices to `R^d_model`.
    - `E_span` is the output of a small MLP that encodes `(mu, log_sigma)` into `R^d_model`.
- Apply cross-attention from this single query to the child set:
  - Project `q_in`, `x_children` with `W_Q, W_K, W_V`.
  - Compute attention weights over the G children.
  - Aggregate to a single vector `gist_raw`.
- Apply output projection and (optional) FFN + residual to produce final `gist ∈ R^d_model`.

**Outputs:**

- `gist`: tensor of shape `[d_model]` to be used as the node latent for that LOD.

**Constraints:**

- GistNet must be **local**: it sees only the G children, no wider context.
- Must be lightweight relative to the main transformer (ideally ≲ 1–5% of compute).

---

### 4.2 LOD Tree Construction

**Inputs:**

- Token embeddings or token-level latents: `[T, d_model]`.
- Configuration:
  - `group_size_l[ℓ]` for each LOD (e.g. `[4, 4, ...]`).
  - `max_lod` (maximum LOD index).

**Behavior:**

1. **LOD0 nodes**:
   - Create one node per token:
     - `latent = token_embedding[i]`.
     - `level = 0`.
     - `span = [i, i]`.
     - `mu = i`.
     - `sigma = sigma_min` (a small fixed value).

2. **LODℓ nodes for ℓ ≥ 1**:
   - For each group of `group_size_l[ℓ]` adjacent children at level `ℓ-1`:
     - Determine the span `[s, e]` that covers all children.
     - Compute `mu = (s + e) / 2`.
     - Compute `sigma` proportional to `(e - s + 1)` (or some function of LOD).
     - Apply GistNet to the children latents to obtain the gist latent.
     - Create a node:
       - `latent = gist`.
       - `level = ℓ`.
       - `span = [s, e]`.
       - `mu`, `sigma`.
       - `children = indices of children`.

3. Continue building LODs until:
   - The remaining number of nodes at the current LOD is ≤ 1, or
   - `max_lod` is reached.

**Outputs:**

- A collection of nodes, each with:
  - `id`
  - `latent`
  - `level`
  - `span`
  - `mu`, `sigma`
  - `children` (list of node ids, or empty for tokens).

---

### 4.3 Tree Flattening

**Inputs:**

- Full set of nodes from tree construction.

**Behavior:**

- Produce a list `ordered_nodes` such that:
  - **Children-before-parent**: for every node, all its descendants appear earlier in the list.
  - Nodes are roughly grouped by time to preserve locality, e.g.:
    - Sweep left-to-right in token time.
    - Whenever a span closes (last child of a gist is emitted), emit that gist node.
- Flattening strategy (example):
  - For each LOD0 token in order, append token node.
  - At positions where LOD1 spans end, append the corresponding LOD1 gist.
  - At positions where LOD2 spans end, append the corresponding LOD2 gist.
  - And so on up to `max_lod`.

**Outputs:**

- `ordered_nodes`: list of node ids in flattened order.
- For each node, its index in the flattened sequence.

---

### 4.4 LOD Dropout and Repacking

**Inputs:**

- `ordered_nodes` + node metadata (`level`, `children`, etc.).
- Configurable dropout probabilities per LOD (e.g. `p_drop[ℓ]`).

**Dropout Rules:**

- **Never drop** the **last node** (in flattened order) for each LOD.
- A parent node may be dropped only if **all its descendants are dropped**.
- Drop decisions may be stochastic but must respect the ancestor/descendant constraints.

**Behavior:**

1. Sample initial “drop/keep” decisions for nodes (subject to “never drop last per LOD”).
2. Enforce parent/child constraints:
   - If a node is kept, all its ancestors must be kept.
   - If a node is dropped and all its siblings are dropped, then parent is eligible for dropping.
3. Create a new kept-node list.
4. Repack kept nodes into a new sequence `[0..N'-1]`:
   - Preserve `(mu, sigma, level, span)` for each node.
   - Update flatten index.

**Outputs:**

- `packed_nodes`: final list of kept nodes in new flattened order.
- Mapping from original node ids to new indices.

---

### 4.5 Transformer Input Encoding

**Inputs:**

- `packed_nodes` with latents `[N', d_model]`.
- Node metadata: `(mu, sigma, level)`.

**Behavior:**

- For each node:
  - Base latent: node latent `z_n ∈ R^d_model`.
  - Add level embedding: `z_n += E_level[level_n]`.
  - (Optional) add node-type embedding (e.g. token vs gist).
- Compute Q/K/V via standard linear projections.
- Apply **Gaussian 2D RoPE** to Q/K using `(mu_n, sigma_n)`.
- Use **standard lower-triangular causal mask** over the flattened index dimension.

**Outputs:**

- Standard transformer hidden states per node, used for losses.

---

### 4.6 Loss Computation

**Token loss (LOD0):**

- For nodes corresponding to tokens at index `t`:
  - Predict next token `x[t+1]` (if it exists).
  - Apply CE loss over logits from that node’s final hidden state.
- Optionally, only supervise a subset of LOD0 nodes for efficiency.

**Gist loss (LOD>0):**

- For each gist node n at level ℓ:
  - Determine a **future span** (e.g. the next group at level ℓ).
  - Compute teacher gist using GistNet on that *future* span (with no gradients).
  - Predict a gist from the node’s hidden state using a small projection layer.
  - Compute MSE between predicted gist and teacher gist.

**Total loss:**

- `L = λ_tok * L_CE + Σℓ λ_gist[ℓ] * L_MSE[ℓ]`

## 5. Non-Functional Requirements

- Training must run on a single GPU (or CPU) for small configs.
- Code should be modular and easy to extend.
- Keep dependency footprint minimal (PyTorch + standard Python libs).

3. **Tests:**
   - Unit tests as described in the TDD.

   - High-level README for how the tree/LOD system works.

## 7. Acceptance Criteria

- End-to-end training loop runs without errors for a small config.
- GistNet is invoked in tree construction, and gradients flow through it.
- Tree flattening obeys children-before-parent ordering.
- LOD dropout respects constraints and produces valid packed sequences.
- CE and MSE losses both decrease over time on a toy dataset.
