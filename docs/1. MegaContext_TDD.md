# Technical Design Document (TDD)
## Project: NanoChat-LM with Multi-LOD GistNet and Tree Context

---

## 1. Codebase Overview

We will extend the existing **nanochat** codebase, which provides a small decoder-only transformer model, with additional modules for:

- Multi-LOD tree construction.
- GistNet summarization.
- Tree flattening and LOD dropout.
- Gaussian 2D RoPE positional encoding.
- Multi-objective loss computation (token CE and gist MSE).

The design emphasizes modularity: each concept (GistNet, tree construction, flattening, dropout, RoPE) is implemented in a separate file or class with clear interfaces.

---

## 2. Modules and Responsibilities

### 2.1 `gistnet.py`

**Class:** `GistNet(nn.Module)`

**Purpose:**  
Local G→1 summarization: given `G` child latents, produce a single gist latent, with no access to global context.

**Signature (initial version):**

```python
class GistNet(nn.Module):
    def __init__(self, d_model: int, d_span: int = 2, n_levels: int = 4):
        super().__init__()
        self.q_base = nn.Parameter(torch.randn(d_model))

        self.level_emb = nn.Embedding(n_levels, d_model)

        # Span encoder: encodes [mu, log_sigma] -> R^d_model
        self.span_mlp = nn.Sequential(
            nn.Linear(d_span, d_model),
            nn.GELU(),
            nn.Linear(d_model, d_model),
        )

        # Single-head attention for simplicity
        self.W_Q = nn.Linear(d_model, d_model, bias=False)
        self.W_K = nn.Linear(d_model, d_model, bias=False)
        self.W_V = nn.Linear(d_model, d_model, bias=False)
        self.W_O = nn.Linear(d_model, d_model, bias=False)

        # Optional small FFN
        self.ffn = nn.Sequential(
            nn.Linear(d_model, 4 * d_model),
            nn.GELU(),
            nn.Linear(4 * d_model, d_model),
        )

    def forward(self, x_children: torch.Tensor,
                level: torch.Tensor,
                mu: torch.Tensor,
                sigma: torch.Tensor) -> torch.Tensor:
        """
        x_children: [G, d_model]
        level: scalar or [1] long
        mu, sigma: scalar tensors (span center and variance/scale)
        returns: [d_model] gist latent
        """
        ...
```

**Forward steps:**

1. Encode span:
   ```python
   span_feat = torch.stack([mu, sigma.log()], dim=-1)  # [2]
   span_emb = self.span_mlp(span_feat)                 # [d_model]
   ```
2. Construct query input:
   ```python
   q_in = self.q_base + self.level_emb(level) + span_emb  # [d_model]
   ```
3. Compute attention:
   ```python
   Q = self.W_Q(q_in.unsqueeze(0))        # [1, d]
   K = self.W_K(x_children)               # [G, d]
   V = self.W_V(x_children)               # [G, d]
   attn_logits = (Q @ K.transpose(0, 1)) / math.sqrt(d_model)  # [1, G]
   attn = attn_logits.softmax(dim=-1)     # [1, G]
   gist_raw = attn @ V                    # [1, d]
   gist_raw = self.W_O(gist_raw)          # [1, d]
   gist = gist_raw.squeeze(0) + q_in      # residual from query
   gist = self.ffn(gist) + gist           # [d_model]
   ```
4. Return `gist`.

**Notes:**

- GistNet is purely local; it uses only child latents and their span/level metadata.
- The same `GistNet` instance can be reused for all levels, with `level` controlling behavior via `level_emb`.

### 2.2 `lod_tree.py`

**Purpose:**  
Build multi-LOD trees from token-level latents and GistNet.

**Data structures (Pythonic, non-optimized):**

```python
@dataclass
class Node:
    id: int
    level: int         # 0 = tokens
    span_start: int    # token index
    span_end: int      # token index (inclusive)
    mu: float          # center of span
    sigma: float       # scale / variance
    latent: torch.Tensor  # [d_model]
    children: List[int]   # child node ids (empty for tokens)
```

**Functions:**

```python
def build_lod_tree(
    token_latents: torch.Tensor,
    group_sizes: List[int],
    gistnet: GistNet,
    sigma_base: float = 1.0,
    sigma_scale: float = 2.0,
) -> List[Node]:
    """
    token_latents: [T, d_model]
    group_sizes: per-level group sizes, e.g. [4, 4, 4] for LOD1..LOD3
    Returns: list of Node objects for all LODs.
    """
    ...
```

**Algorithm Outline:**

1. Initialize LOD0 nodes:
   - For each token index `t`:
     - `level=0`, `span=[t, t]`, `mu=t`, `sigma=sigma_base`, `latent=token_latents[t]`, `children=[]`.

2. For `ℓ` from 1 to `len(group_sizes)`:
   - Group nodes from previous level into groups of size `G = group_sizes[ℓ-1]`:
     - For group index `g`:
       - Collect children `children = nodes_prev[g*G : (g+1)*G]`.
       - If group incomplete at end, may:
         - either skip or allow smaller groups (configurable).
       - Determine span:
         - `s = min(child.span_start)`, `e = max(child.span_end)`.
       - Compute:
         - `mu = 0.5 * (s + e)`.
         - `sigma = sigma_base * (sigma_scale ** ℓ)` or proportional to `(e - s + 1)`.
       - Call GistNet on children latents:
         - `x_children = torch.stack([c.latent for c in children], dim=0)`.
         - `latent = gistnet(x_children, level=ℓ, mu=mu, sigma=sigma)`.
       - Create new Node with new id, `children=[c.id for c in children]`.
   - Append new LODℓ nodes to global node list.

3. Stop when:
   - No more groups can be formed, or
   - Reached configured max LOD.

**Outputs:**

- A list of all nodes (LOD0 + all created LODℓ).

### 2.3 `tree_flatten.py`

**Purpose:**  
Convert the hierarchical node set into a single, causal sequence.

**Function:**

```python
def flatten_tree(nodes: List[Node]) -> List[int]:
    """
    nodes: full list of Node objects
    Returns: ordered list of node ids (flattened sequence),
             such that children always come before parents.
    """
    ...
```

**Flattening Strategy:**

- We can assume nodes are grouped by level; we will generate the sequence explicitly:
  1. Collect nodes per level: `nodes_by_level[ℓ]`.
  2. For LOD0:
     - Sort by `span_start` (equivalently, token index).
  3. For higher LODs:
     - Insert each gist node at the index where its span ends, after all children that share that span.
- A robust approach:
  - Build an intermediate structure keyed by token index:
    - For each LOD0 node, append its id at `time_bucket[span_end]`.
    - For each higher-LOD node, append its id at `time_bucket[span_end]` (after its children).
  - Iterate `time_bucket` from low to high token indices:
    - Append contents (tokens first, then gists by level order) to flattened sequence.

**Invariants:**

- For each node, all descendants are guaranteed to have `span_end <= node.span_end`, and will appear earlier in the flattened sequence.

### 2.4 `tree_dropout.py`

**Purpose:**  
Perform node-level dropout and repack the sequence, respecting hierarchical constraints.

**Function:**

```python
def apply_lod_dropout(
    nodes: List[Node],
    flat_ids: List[int],
    n_levels: int,
    p_drop_per_level: List[float],
) -> Tuple[List[Node], List[int], Dict[int, int]]:
    """
    nodes: full node list
    flat_ids: flattened node ids (pre-dropout)
    n_levels: total number of levels
    p_drop_per_level: dropout probability per level (len = n_levels)
    Returns:
      kept_nodes: nodes after dropout (subset of input nodes)
      packed_ids: flattened node ids for kept_nodes (new order)
      id_remap: dict old_id -> new_id
    """
    ...
```

**Algorithm Sketch:**

1. Identify last node per level in the flattened order:
   - Traverse `flat_ids` from start to end.
   - Track last index at which each `level` appears.
   - These are **forced-keep** nodes.

2. Initialize `keep[old_id]`:
   - Set `keep[last_id[level]] = True` for all levels.
   - For other nodes, sample:
     - `keep[id] ~ Bernoulli(1 - p_drop_per_level[level])`.

3. Enforce child→parent constraints:
   - If a node is kept, all of its ancestors must be kept:
     - For each kept node, walk up via `children` relationships to mark ancestors as kept.
   - If a node is dropped but some child is kept, re-mark node as kept.

4. Construct `kept_nodes` list:
   - Filter original `nodes` by `keep[id]`.
   - Build `id_remap` mapping old ids to new ids.

5. Build `packed_ids`:
   - Iterate original `flat_ids`; if `keep[id]`, append `id_remap[id]`.

**Result:**

- A valid flattened sequence of kept nodes, with all ancestors present when required, and last nodes per level always kept.

### 2.5 `gaussian_rope.py`

**Purpose:**  
Implement a 2D RoPE-like positional encoding using `(mu, sigma)`.

**Interface:**

```python
def apply_gaussian_rope(
    q: torch.Tensor,  # [N, n_heads, d_head]
    k: torch.Tensor,  # [N, n_heads, d_head]
    mu: torch.Tensor, # [N]
    sigma: torch.Tensor, # [N]
    rope_dim: int,
) -> Tuple[torch.Tensor, torch.Tensor]:
    """
    Applies 2D roations in (mu, sigma) space to q and k.
    Returns: (q_rot, k_rot)
    """
    ...
```

**Design (conceptual):**

- Split `d_head` into 2 or 4 sub-blocks.
- Use standard RoPE-style sinusoidal angles derived from:
  - `mu` for time dimension.
  - `sigma` (or log σ) for scale dimension.
- For each sub-block, compute rotations based on:
  - `theta_mu(mu, frequency)`, `theta_sigma(sigma, frequency)`.
- Combine them into a 2D rotation that encodes both time and scale.

**Implementation Simplification (for POC):**

- For now, we can:
  - Use standard RoPE on half of the head dimension with `mu`.
  - Use an independent standard RoPE on the other half of the head dimension with `log_sigma`.
- This is still a “Gaussian-ish 2D RoPE” and is simple to implement.

### 2.6 `model.py` (nanochat extension)

**Purpose:**  
Integrate multi-LOD tree, GistNet, and Gaussian RoPE into the nanochat model.

**Key changes:**

- Instead of feeding only token embeddings `[T, d_model]`, we feed a flattened LOD tree `[N', d_model]`.
- Add positional metadata `(mu, sigma, level)` per node.
- Modify Q/K computation:
  - After linear projection, apply `apply_gaussian_rope` to q/k using `(mu, sigma)`.
- Maintain everything else (attention, MLP, residuals, etc.) as in nanochat.

**Model forward signature:**

```python
def forward(
    self,
    token_ids: torch.Tensor,    # [B, T]
    attention_mask: Optional[torch.Tensor] = None,
    ...
) -> Dict[str, torch.Tensor]:
    """
    Steps:
      1. Embed tokens -> token_latents
      2. For each sequence in batch:
         - Build LOD tree with GistNet
         - Flatten tree
         - Apply dropout & repack
      3. Batch-pack all sequences into [N_total, d_model] + metadata
      4. Run transformer
      5. Compute CE and MSE losses

    Returns:
      {
        "logits": token_logits_for_loss_positions,
        "loss_ce": ce_loss,
        "loss_mse": mse_loss,
        "loss_total": total_loss,
      }
    """
    ...
```

To keep the initial POC simpler, we can:

- Start with batch size 1 in the tree-building code.
- Later generalize to batching once the single-sequence pipeline works.

### 2.7 `training.py`

**Purpose:**  
Implement training loop to optimize the model with both CE and MSE losses.

**Key steps per batch:**

1. Obtain `token_ids` for batch.
2. Embed tokens with nanochat’s embedding layer.
3. For each sequence in batch:
   - Build LOD tree via `build_lod_tree`.
   - Flatten tree via `flatten_tree`.
   - Apply LOD dropout via `apply_lod_dropout`.
4. Collate all sequences into a single packed tensor:
   - `node_latents`, `mu`, `sigma`, `level`, and index mapping for token positions.
5. Run model forward:
   - Apply transformer over packed nodes.
6. Compute **token CE loss**:
   - Use node-index-to-token-index mapping to select LOD0 nodes and their next-token targets.
7. Compute **gist MSE loss**:
   - For each kept gist node:
     - Identify future span.
     - Build teacher gist with GistNet (no grad).
     - Predict gist from its transformer output.
     - Compute per-node MSE.
8. Combine losses and backprop.
9. Log losses and optionally some diagnostics (e.g., norms of gists, distribution of LOD nodes kept).

## 3. Test Plan (TDD-Level)

### 3.1 Unit Tests

1. **GistNet**
   - Input: random `x_children` with shape `[G, d]`.
   - Assert: output shape `[d]`.
   - Assert: attention weights sum to ~1 across children.
   - Check: varying `level`, `mu`, `sigma` changes output in a non-trivial way.

2. **Tree Builder**
   - For a toy sequence of length 8 and group_size=[4]:
     - Expect:
       - 8 LOD0 nodes.
       - 2 LOD1 nodes, spans `[0..3]` and `[4..7]`.
       - Correct `mu` and `sigma` values (or close within tolerance).
     - Verify each LOD1 node’s children span matches its span.

3. **Tree Flattening**
   - Using a fixed small tree (like the 8-token example):
     - Flatten.
     - Verify that for each node, all children appear at lower indices.
     - Manually inspect example ordering (tokens, then gists inline at span ends).

4. **Dropout**
   - For a known tree and LOD layout:
     - Set `p_drop_per_level` to non-zero.
     - Run `apply_lod_dropout`.
     - Assert:
       - Last node at each level is always present.
       - If a node is present, all its ancestors are present.
       - `packed_ids` only contain kept nodes.
       - No invalid node indices remain.

5. **Gaussian RoPE**
   - Construct Q/K for a few nodes with different `(mu, sigma)`.
   - Apply `apply_gaussian_rope`.
   - Check:
     - Norms of q/k are preserved.
     - Changing `mu` or `sigma` changes phases.

6. **Model Integration**
   - Use a very small configuration (e.g., d_model=16, T=8, group_size=[4]).
   - Run a single forward pass:
     - Ensure losses are finite.
   - Run a forward+backward+optimizer step:
     - Ensure no errors and parameters update.

---

### 3.2 Integration Tests

- **End-to-End Tiny Training**
  - Run training loop for a small number of steps on dummy data.
  - Assert that:
    - `loss_total` decreases or at least doesn’t diverge rapidly.
    - `loss_mse` is non-zero and gets gradients (by checking grad norms on GistNet).

- **Tree Geometry Sanity Check**
  - For a batch with fixed tokens:
    - Dump tree structure (spans, LODs, flattened order).
    - Confirm it matches expected shape: children before parents, LOD coverage over time.

## 4. Future Extensions (Design Hooks)

- **Inference Drafting**
  - Design ensures GistNet is reusable at inference:
    - We can later create “planned” future gists and feed them to token-level decoding.
- **Learned Tree Subset Selection**
  - LOD dropout is currently random with constraints; we can later:
    - Replace dropout with a learned scoring module that picks which nodes to keep under a context budget.
- **Alternative GistNet Architectures**
  - GistNet is a self-contained module; swapping in different architectures (e.g., small transformer encoder) should only require local changes.
